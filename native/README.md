# Native shells

Capacitor projects that package the web app in the repo root for the App Store
and Google Play. Everything npm lives in this directory; the web app itself
stays dependency-free and deploys to GitHub Pages exactly as before.

## How it fits together

- `sync-www.mjs` rebuilds `www/` by parsing the `SHELL` list out of `../sw.js`
  and copying exactly those files (plus `index.html`). SHELL is already the
  test-enforced inventory of everything the app needs, so the app bundle can
  never drift from the web app. `sw.js` itself is never copied — the native
  shell has no service worker on purpose.
- `../src/native.js` is the only bridge the web code has to Capacitor. It
  detects the injected `window.Capacitor` and talks to the plugin proxies; on
  the web every function no-ops. No `@capacitor/*` JS is ever imported — the
  packages here exist so `cap sync` wires their **native** code into
  Gradle/CocoaPods.
- `assets/` holds the store-asset sources (1024 icon, adaptive foreground and
  background, 2732 splashes), generated by `node ../tools/make-icons.mjs`.
  `npm run assets` fans them out to every platform density.

## ⚠️ Never change `androidScheme`

WebView storage is keyed to the serving origin (`https://localhost` on Android,
`capacitor://localhost` on iOS). Changing `server.androidScheme` in
`capacitor.config.json` after release moves the app to a new origin and wipes
every player's streaks and stats. Don't.

The same data survives eviction via a mirror: `src/native.js` snapshots the
`pwg.v1.*` localStorage namespace into Capacitor Preferences (debounced, plus a
hard flush on app pause) and restores it at boot when localStorage comes up
empty.

## Android (works on this Linux machine)

Toolchain: JDK 21 at `~/Android/jdk`, SDK at `~/Android/Sdk` (command-line
tools, platform 35, build-tools 35.0.0, platform-tools). `local.properties` in
`android/` points at the SDK; export `JAVA_HOME=~/Android/jdk` for Gradle.

```sh
npm run sync                  # rebuild www/ + cap sync both platforms
cd android && JAVA_HOME=~/Android/jdk ./gradlew assembleDebug
# → android/app/build/outputs/apk/debug/app-debug.apk
adb install app/build/outputs/apk/debug/app-debug.apk   # device or emulator
```

Debug a running app from desktop Chrome via `chrome://inspect`.

Release build:

1. Once: `keytool -genkeypair -v -keystore ~/keystores/plouffe-upload.jks
   -alias upload -keyalg RSA -keysize 2048 -validity 10000` — keep the
   keystore OUT of the repo, back it up, and reference it from an uncommitted
   `android/keystore.properties`.
2. Add the standard `signingConfigs.release` block reading that file, then
   `./gradlew bundleRelease` → `app-release.aab` for the Play Console. Opt in
   to Play App Signing on first upload.

Config that must not regress: `minSdkVersion = 26` (`variables.gradle`),
`android:screenOrientation="portrait"` and the `VIBRATE` permission
(`AndroidManifest.xml`). The runtime WebView floor (dvh + `:has()`) is guarded
in `boot()` with an update notice.

## iOS (needs the Mac)

The project in `ios/` is generated and configured (iPhone-only, deployment
target 16.0, portrait-only, `ITSAppUsesNonExemptEncryption = NO`); CocoaPods
runs on the Mac.

```sh
git clone <repo> && cd cryptogram/native
npm ci && npm run sync        # cap sync runs pod install
npx cap open ios              # Xcode: set the team, automatic signing
```

Run on a device, then Product → Archive → Distribute → TestFlight.

## Versioning

Bump in lockstep for every release:

- Android: `versionCode` + `versionName` in `android/app/build.gradle`
- iOS: `CURRENT_PROJECT_VERSION` + `MARKETING_VERSION` in Xcode

## Store submission checklist

- **Accounts** (start first, they gate the calendar): Apple Developer $99/yr
  (1–2 days), Google Play $25 once (identity check can take days). Personal
  Play accounts must run a closed test with 12+ testers for 14 days before
  production access.
- **Privacy**: the app collects nothing and sends nothing — declare "Data Not
  Collected" (Apple) and all-No on the Play Data Safety form. Both stores
  require a privacy policy URL: a static `privacy.html` on the GitHub Pages
  site is enough.
- **Apple guideline 4.2** (minimum functionality) is the real review risk for
  wrapped web apps. In the review notes, say it plainly: fully offline game,
  no web dependency, 8 games, daily puzzles with streaks, custom in-app
  keyboard, native haptics/share/status bar, state survives app kill.
- **Assets**: Apple — the 1024 icon (generated), ≥3 6.7" screenshots
  (1290×2796), description, keywords, support URL. Play — 512 icon, 1024×500
  feature graphic, ≥2 phone screenshots, content rating questionnaire, target
  audience 13+.
- **Device checklists** before each submission (emulator/TestFlight):
  - back gesture: closes sheet → leaves game → minimizes app, never kills
  - force-stop and relaunch mid-puzzle: board, streaks intact
  - clear WebView storage, relaunch: mirror restores streaks
  - share opens the OS sheet; keys tick with haptics (including iOS)
  - no service worker registered; status bar legible in both themes
